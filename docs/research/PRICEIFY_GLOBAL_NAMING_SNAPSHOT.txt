Global naming principles
* Use “Test” instead of “Experiment” everywhere (“Price test”, “Offer test”, “New test”, “Tests dashboard”).
* Keep CRO language where it helps: Revenue per visitor, Confidence, Lift.
* Talk in Products / Collections and Prices / Offers, not generic “campaigns”.

Mini‑glossary for the team
To keep everyone naming things the same way:
         * Test – A single price or offer comparison you run in Priceify.
         * Price test – Changes the actual price shown to shoppers, without a crossed‑out original.
         * Offer test – Shows a sale price with the original price crossed out.
         * Control – The current price your store already uses.
         * Variation – A different price or offer you’re testing against control.
         * Revenue per visitor – Revenue generated divided by number of visitors who saw the test.
         * Confidence – How sure the maths is that one variation is better than another.
         * Minimum visitors per variation – The number of visitors each variation must see before results are calculated.
         * Price locations – The pages where prices appear (product, collection, cart, search, home).
         * Theme selector – The CSS selector Priceify uses to find a price on your theme.[ppl-ai-file-upload.s3.amazonaws]

3. Text generation rules
3.1 Test line
Format:
Test: {name} — {typeLabel} · {productsText} · {pricingText}
Type label:
         * price → "Price test"
         * offer → "Offer test"
Products text:
         * If productsScope === 'all' →
"{productsCount} products · All products"
         * If productsScope === 'picked' →
"{productsCount} products · Picked products"
Pricing text:
            * ai_suggested → "AI suggested prices"
            * bulk_adjust → "Bulk adjusted prices"
            * manual → "Manual prices"
3.2 Traffic line
Format:
Traffic: {trafficAllocationPercent}% of eligible visitors · {variationSummary}
Variation summary:
Take variations array and join control + non‑controls:
            * Control first:
"Control {trafficPercent}%"
            * Each variation:
"Var A {trafficPercent}%", "Var B {trafficPercent}%", etc.
Implementation example:
const control = variations.find(v => v.isControl);
const others = variations.filter(v => !v.isControl);


const variationSummary = [
  control ? `Control ${control.trafficPercent}%` : null,
  ...others.map(v => `${v.name} ${v.trafficPercent}%`),
]
  .filter(Boolean)
  .join(' · ');
Result example:
Traffic: 100% of eligible visitors · Control 34% · Var A 33% · Var B 33%
3.3 Audience line
Format:
Audience: {visitorsText} · {devicesText} · {sourcesText} · {countriesText}
Visitors text:
               * audienceSegment === 'all' → "All visitors"
               * new → "New visitors"
               * returning → "Returning visitors"
Devices text:
               * If all three in array → "All devices"
               * Otherwise join enabled ones, e.g. "Desktop & Mobile" / "Mobile only".
Sources text:
               * If all sources selected → "All sources"
               * Otherwise join, e.g. "Search & Email".
You can map TrafficSource → labels:
               * direct → "Direct"
               * search → "Search"
               * social → "Social"
               * email → "Email"
               * paid_ads → "Paid ads"
               * referral → "Referral"
Countries text:
               * countriesMode === 'all' → "All countries"
               * include → "Include: {countryList}"
               * exclude → "Exclude: {countryList}"
Where countryList is “UK” / “US, CA” etc.
Example:
Audience: All visitors · All devices · All sources · All countries
3.4 Results line
Format:
Results: Primary: {primaryLabel} · {confidenceLevelPercent}% confidence · {minimumVisitorsPerVariation} visitors/variation
Primary label:
               * revenue_per_visitor → "Revenue per visitor"
               * conversion_rate → "Conversion rate"
               * aov → "Average order value"
Example:
Results: Primary: Revenue per visitor · 90% confidence · 5,000 visitors/variation
3.5 Safety line
Format when guardrail ON:
Safety: Guardrail ON · Pause if Rev/visitor drops >{thresholdPercent}% vs control, after {minVisitorsPerVariation} visitors/variation
Use guardrail.thresholdPercent and guardrail.minVisitorsPerVariation.
Format when guardrail OFF:
Safety: Guardrail OFF
Example:
Safety: Guardrail ON · Pause if Rev/visitor drops >10% vs control, after 1,000 visitors/variation
(or whatever default you set).
